# 🤔 Hypothetical Scenario Questions

*"Imagine you…" questions test structured thinking, not memory. Clarify, assume, outline, weigh trade-offs, and define success — in 3–4 minutes.*

## 🧭 The framework
<!-- related: behav-12, behav-26 -->

```mermaid
flowchart LR
  C[Clarify goal and constraints] --> A[State assumptions] --> O[Outline approach] --> T[Discuss trade-offs] --> M[Define success metrics]
```

| Step | What to say |
|---|---|
| Clarify | Who is it for? What does success look like? Budget, deadline? |
| Assume | "I'll assume X; tell me if that's wrong." |
| Outline | 3–5 phases, broad first, then narrow |
| Trade-offs | What you'd give up and why |
| Metrics | How you'd know it worked; checkpoints |

> 🔑 Time-box to 3–4 minutes, then invite direction: "Which part should I go deeper on?"

## 🗂️ Scenario types
<!-- related: behav-11, behav-28, behav-40 -->

### 🎉 Planning an event or initiative
- Objective + success measure → audience → stakeholders → logistics → risks → timeline.

### 🛠️ Technical improvement
- e.g. "halve app startup time": baseline → biggest contributors → prioritise by effort/impact → ship behind a flag → track the metric.

### 🐛 Users are confused by a feature
- Gather signals (analytics, support tickets, sessions) → hypothesis → small test → iterate.

### ⏰ Team keeps missing deadlines
- Diagnose (estimates? scope creep? dependencies?) → change one thing at a time → measure predictability.

### 📶 Scale or capability shift
- e.g. 10× traffic or offline-first: constraints → bottlenecks → phased plan → rollback path.

## 💬 Delivery tips

- Think aloud; asking for a moment to structure is fine.
- Show user empathy explicitly.
- Invite collaboration: "Does that match what you'd prioritise?"
- Anchor in real experience when possible: "When I faced something similar…".

> 📝 Practice: run one scenario per type aloud against a 4-minute timer.
